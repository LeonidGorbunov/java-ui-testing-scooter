# Java UI Testing Scooter Project

**Контекст и цели проекта**: проектирование масштабируемой архитектуры UI-автотестов на основе паттерна Page Object Model (POM) для верификации критических пользовательских сценариев и валидации фронтенд-компонентов.

**ТЗ (вид работ)**: автоматизация пользовательского интерфейса (UI Web Automation), разработка инфраструктурных шаблонов тестов, параметризация сквозных сценариев (E2E), реализация фабрики драйверов (Factory Pattern) и кроссбраузерное тестирование.

**Продукт**: веб-интерфейс сервиса проката Яндекс.Самокат.

**Выполненные задачи**:
1. **Архитектурный шаблон и фабрика**: разработан базовый класс `TestTemplate` с инкапсулированной логикой инициализации пред-/постусловий тестов (`@Before`/`@After`). Спроектирован класс `WebDriverFactory`, реализующий паттерн фабрики для динамического конфигурирования и переключения браузеров (Chrome/Firefox) через системные свойства (`System.getProperty`).
2. **Паттерн Page Object (POM)**: осуществлена декомпозиция интерфейса веб-приложения на изолированные классы страниц (`SamokatMainPage`, `SamokatOrderFirstPage`, `SamokatOrderSecondPage`, `SamokatTrackPage`), полностью инкапсулирующие локаторы элементов (XPath/ID) и методы взаимодействия.
3. **Отказоустойчивость локаторов и динамические ожидания**: реализована стабильная обработка загрузки интерфейса посредством явных ожиданий `WebDriverWait` и класса `ExpectedConditions`. Для элементов со сложной динамической структурой (аккордеоны, дропдауны метро, выбор сроков аренды) применены строковые шаблоны XPath с форматированием на лету (`String.format`).
4. **Оптимизация E2E-сценариев**: сквозной процесс заказа локализован в приватный метод `runOrderFlow()`, что позволило без дублирования кода (принцип DRY) верифицировать успешность создания заказа из двух различных пользовательских точек входа (верхняя и нижняя кнопки «Заказать» со скроллом через `JavascriptExecutor`).
5. **Тестовые сценарии и параметризация**: спроектированы параметризованные тест-комплекты на базе JUnit 4 для массовой проверки текстовых панелей аккордеона и алертов валидации обязательных полей. Интегрированы тесты логики редиректов и переключения между вкладками браузера (`getWindowHandles`), а также негативные тесты на ввод несуществующего номера заказа.

**Область тестирования (Scope)**: сквозные UI-сценарии оформления заказов, валидация полей ввода и вывод сообщений об ошибках, логика раскрывающихся списков, управление вкладками браузера при интеграционных редиректах, кроссбраузерность компонентов верстки.

**Окружение**: Java (JDK 11), JUnit 4, Selenium WebDriver, WebDriverManager, Maven.
